# Project knowledge

Some projects have a knowledge folder at `/knowledge`. It holds the project's instructions in `/knowledge/CLAUDE.md` and the specs they refer to. I maintain it by hand outside the repo, and you can read it but not change it.

- Everything in it is the current version. I keep older versions where you can't see them.
- The folder is live. When I say I've updated a document, reread it instead of relying on an earlier read.
- Treat specs as context, not truth. They were written as loose guides before development started, so details have drifted. When a spec and the code disagree, trust the code and point out the mismatch.
- When a document needs to change, give me the edits in chat, ready to paste. Name the file and section, quote the text being replaced, and give the new text.
