---
name: "feature-doc"
description: "Generate a feature overview documentation"
---

Can you write a Markdown overview document that will serve as a guide for our development. The guide should be an overview, it should describe the feature, talk about the basic foundation and how it will work. Someone reading the file should be able to get up to speed on the feature and understand its purpose and how it'll be implemented. Only describe what is to be built and the specifications for it, do not include self-referential prose like "we decided on x", "this was updated from y", etc. Other people and chat contexts later will not have access to any back and forth we had on design decisions or other context, so this document should not be unnecessarily self-referential or verbose. The tone should be imperative.
